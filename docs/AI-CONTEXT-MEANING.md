# AI 此处释义建议

2026-10-26。源码功能，已发布的 v0.3.3 安装包尚未包含本批更新。

## 使用流程

在真题中点词或划选，打开“保存此处词义”或“收藏原文短语”，也可以在收藏详情页使用“AI 建议此处释义”。只有主动点击才发起请求，使用设置中已有的 AI 服务、凭据和模型；未配置时显示设置入口，手动填写始终可用。

请求发送当前目标表达、归一词形、保存的上下文、目标在上下文中的位置和出处标签。不会附带用户正在编辑的释义、备注、其他收藏、聊天历史或整篇文章。服务凭据仅用于对所配置接口鉴权，不作为原文提示内容发送。每次请求最长 60 秒，可点击“停止生成”；切换收藏或离页会取消请求并隔离迟到结果。

模型提供 1 至 3 个候选，每项包含“此处释义”“语境解释”“原文依据”。候选明确标为待确认，不自动写入收藏、AI 缓存、聊天或练习卡，也不覆盖正在输入的文字。原文依据必须逐字匹配保存的上下文，并覆盖指定的那次目标；例如第二处 `sets` 不能拿第一处日落语句充当依据。这里只校验材料一致性，释义是否恰当仍需用户核对。

点击“采用此候选到释义草稿”后，释义输入框会替换为所选文字，可以继续修改。确认后仍须点击原来的“保存语境义/保存短语/保存修改”。不采用就可以继续手写；已采用时也可点击“保留文字，改为手动编辑”，去除本次 AI 来源标记而保留文字。

保存后，详情会标明“AI 辅助，经用户确认”，人工改过候选会另行标记。保留所用模型、生成/确认时间、原候选、解释、真实原文依据及是否修改。不保存服务密钥、接口地址或其他候选。只编辑备注/标签不会抹掉原有来源；之后直接手写更改释义会去掉旧 AI 标记，防止把新文字继续归给旧模型。

## 原文变化与边界

- 新划选在生成前后及采用保存时都核对真实原文摘要和目标身份；原文变化后要求重新划选。
- 已有收藏按保存时的上下文生成。原文已变更或退休时，候选明确注明使用旧上下文；不会冒充当前原文或重新定位。生成期间收藏修改、回收或来源状态变化会拒绝旧结果。
- 缺少可靠目标位置的旧收藏不猜测出现位置，可继续手动填写或重新划选。
- AI 候选有效期十分钟，绑定发起窗口、目标、收藏版本及候选序号。过期时重新生成，或保留文字改为手动编辑再保存。
- 重复收藏仍保留原释义；保存失败保留草稿和候选供重试，成功操作重放不会重复收藏。编辑沿用版本校验，写盘失败整体回滚。
- 题目、字典释义、原生词掌握状态和旧卡答案不随 AI 建议自动修改；已保存收藏仍需审阅制作练习卡。旧卡保留当时版本。

JSON 收藏导出会保留已确认的 `meaningProvenance`；Anki 文本背面及新制卡的来源正文保留 AI 辅助标记。完整恢复仍使用数据库备份，未新增 JSON 导入功能。相关步骤见 [LEARNING-EXPORT.md](LEARNING-EXPORT.md)。

## 实现与验证

新增 `electron/phrase-suggestions.cjs`、`PhraseSuggestion.vue` 和 `phrase:suggest` IPC，复用已有 `withAiRequest` 与前端 `createAiTasks`。主进程重新获取可信来源，不使用前端提交的正文；严格检查 JSON 候选字段、数量、长度、重复与原文依据，普通文本渲染，不执行模型输出中的 HTML 或动作。

`phrase_item` 增量添加 `meaning_provenance TEXT`，旧记录为空，手动操作旧哈希兼容。生成后的随机令牌及候选仅存在主进程内存，窗口关闭或过期清理；保存时才将所选候选的白名单来源信息与收藏同事务持久化。单窗口最多保留八批待确认建议，全局最多六十四批。新请求不会让同窗口更早的迟到生成覆盖新结果。

运行 `npm run test:phrase-ai`：20 项数据/状态、21 项真实 Electron 界面检查。包括真实第二处划选、无配置手写、只读生成、伪造依据、重复/非法结果、取消与迟到、切换目标、人工改写、来源过期、保存回滚、幂等、HTML 转义、JSON 导出及重启。界面测试发现采用信息响应式对象无法通过 IPC 的问题，已将传输字段转为普通对象，采用后保存路径验证通过。

相关短语、语境义、练习卡、拼写/填空、导出以及共用 AI 取消回归合计 **126 项数据/状态、147 项真实界面检查**通过，生产构建通过。所有模型请求使用本地模拟接口，没有真实用户数据修改或付费请求；未验证任一实际模型的释义质量，未运行无关全量 CI。当前仅交付源码，未重建分发库或安装包，v0.3.3 发行标签与附件不变。
