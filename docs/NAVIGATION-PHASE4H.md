# 阅读与背诵导航恢复：第四批 4H

日期：2026-10-19，源码版本保持 0.3.1。

## 问题与修复

- 背诵异步加载缺少身份校验，切卷后旧请求或错误可覆盖当前材料；加载失败会一直显示加载中。现在按请求代次与考次校验，卸载即失效，明确显示失败/缺失并允许重试或返回考次选择。回到无考次入口时重新加载列表。
- 阅读到背诵仅传数组下标，背诵返回阅读不传篇章。现在往返都传本地稳定 passage ID，兼容旧 p 下标链接；同一组件只改查询参数也会定位。背诵筛除无译文篇章后，仍按原篇章身份定位。
- 阅读进度只存 idx，内容排序或补入篇章后容易错位。新记录增加 passageId，优先按身份恢复；旧记录成功读取后升级。已消失的稳定身份不套用旧下标/滚动。非法 JSON 或字段类型不会阻止阅读，破损 JSON 在下次保存时重建有效记录，字号与滚动范围校验。
- 加载过程中展示 watcher 可能写坏目标考次的旧进度，切卷时展示偏好与解析揭示没有全部清理。加载就绪前暂停保存，先读取快照、恢复渲染，再允许保存；按已加载考次身份保护写入。切卷先重置解析揭示、布局、翻译模式和字号，再恢复该卷自己的偏好。
- 阅读滚动监听绑定在初始加载占位节点，正文替换节点后监听丢失。改为在正文模板绑定被动滚动事件，离页和正常关闭前同步保存。去掉固定 500ms 恢复滚动的回调，改为 Vue 渲染完成后恢复，避免随后覆盖用户位置。
- 背诵滚动也改为等待 Vue 渲染并校验页面/篇章身份；对齐行发生变化时重置按旧行下标保存的语言切换和已呈现数量。

## 行为边界

背诵继续每次从空白开始，不新增跨会话的背诵进度记忆。稳定 ID 是当前用户数据库中的 passage.id；数据库恢复时原有 epoch 清理机制继续清除旧阅读位置。已删除篇章回到安全的首篇，不猜测接替篇章。正文加载失败提供重试，收藏高亮读取失败不再阻断正文和作答恢复。

本批修改前端状态与导航，不改数据库 schema、内容库、作答保存协议或框架。所有应用验证使用独占临时 userData。
