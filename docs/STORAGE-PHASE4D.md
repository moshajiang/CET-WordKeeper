## 测量与取舍

`node scripts/storage-profile.cjs` 调用实际主进程函数，只使用分发种子和独占临时数据库。基准使用 Node v24.19.0，种子 13,254,656 字节；查询样本为 1,000 生词、10,000 出处、20,000 复习日志。同一次运行在相同数据上删除/添加索引后比较，采用 3–5 次中位数；这些是本机样本，不是最低配置承诺，也不是完整窗口启动时间。

基线初始化首次 1,396ms、既有库中位 937ms；种子整库保存 16ms、事务保存 20ms，填充样本保存 20ms；词频重建中位 963ms。落地后的独立复测，在同一次运行的无/有索引对照中列表为 559.24/6.39ms、队列为 344.32/0.49ms、统计为 1.65/0.78ms；整库事务保存 19.83ms，既有库初始化 1,126ms，词频重建 1,316ms。绝对耗时存在主机运行波动，不能据此声称启动或重建已加速；查询计划与两轮有/无索引对照均确认查询收益。词频重建仅内容变更时运行，后续仍可优化。查询计划由逐词 `SCAN h` 变为使用 `idx_word_hit_word` 的索引查询。

本步为 word_hit(word)、review_log(word_id)、review_log(reviewed_at)、user_word(status,due) 添加幂等索引。重复收藏同一出处、相同状态/笔记/设置跳过整库保存；新出处仍写入，设置和笔记写盘失败恢复内存。保留 sql.js 的事务快照和同步原子持久化：当前证据优先支持索引及减少无效保存，尚不足以承担内容库/用户库拆分的迁移成本。没有宣称主线程阻塞或所有存储性能问题已经解决。

## 恢复协议

1. 设置页选择 `.db/.bak`，只读校验 SQLite 文件头、大小（256 MB 上限）、完整性、原始应用表/列、已知格式版本；拒绝触发器和视图。兼容 0.3.1 备份缺少新增草稿/复习操作表的情况。预览仅显示路径、记录数，不暴露 Key。未标注版本的未知未来库无法保证识别，缺少原始应用结构的任意 SQLite 不接受。
2. 用户在预览中明确点击“确认恢复并重启”。令牌只绑定本次已校验字节，10 分钟有效；取消/重新选择使旧令牌失效。预览后原文件变化不会改变将恢复的内容。
3. 将当前完整内存快照和选中备份分别写为随机唯一的恢复前备份及候选，核对 SHA-256，flush 后原子发布固定位置的恢复任务。此时不替换当前库。准备失败不发布任务；留下的恢复前备份保留，不自动删除。
4. 发布成功即封锁 SQL 写入和持久化，结束旧进程；旧窗口的 AI 返回和草稿不能再写入。禁用本次退出的 updater 自动安装，避免恢复重启被安装流程截获。
5. 新进程获得单实例锁后、打开用户库前，验证任务和文件哈希，将任务标记 applying，然后原子替换。正常启动执行既有 schema/内置内容迁移；失败则用恢复前备份回退并重新打开。回退本身失败时停止启动，保留文件，不新建空库。
6. 完成后持久化新 epoch 与恢复前备份位置，标记 completed、移除任务。若进程在 applying 时中断，下次保守回退；completed 的残留任务只补全状态，不再次覆盖后续数据。候选及恢复前备份暂不自动清理。
7. Vue 挂载前检查 epoch；成功恢复或必要回退后清理旧数据库的浏览器作答/作文恢复副本与阅读位置，保留主题和其他应用键。清理失败时不挂载阅读器，避免旧副本回灌。备份里的草稿由正常数据库逻辑恢复。

备份导出同样校验快照后原子写目标文件；拒绝覆盖正在使用的库、同文件硬链接及恢复保留文件。备份包括 AI 配置与 Key，设置页明确提示妥善保管。恢复是完整替换，不做跨库合并；内置材料随后仍按现有版本迁移协议更新。
