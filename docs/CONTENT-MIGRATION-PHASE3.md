# 第三批：内置内容身份与迁移

2026-10-19；源码开发记录，未发布或替换已安装程序。

## 内容身份与匹配

`electron/content-sync.cjs` 取代按数组下标回填的逻辑。内置考次按级别/年月/套号建立 source_id，篇章按 section/seq，带题号题目按题号；无题号题目按题型、题干和选项的哈希。之后可在 seed JSON 显式保留 source_id，允许纠正文案、题号和篇章序号时延续身份。身份使用父级命名空间，重复身份种子拒绝迁移。

旧库仅在 imported=0 的考次内认领内容，保留本地 exam/passage/question 行 ID，不根据题目数组位置补答案。补回题目带 source_order，恢复篇章中的显示顺序。同名 imported=1 材料独立保留。

已有非空错误正文、答案、解析、翻译、范文和 rows 可以修正。种子未提供的可选字段保留本地 AI 内容；这意味着主动清空可选内容需要以后增加显式删除标记。无法确定身份的重复旧记录或被移除内容设 retired=1，并在 content_history 保存旧字段；旧 user_answer、mistake、word_hit 等引用保留。当前列表、阅读器、评分和词频只使用有效内容。重复考次的原学习记录归属原行，不猜测合并。

## 事务与恢复

整个目录先验证，再在 SQLite 事务内更新。事务提交后才导出 sql.js（export 会关闭连接，不能在未提交事务中调用）。需要写盘时先按原磁盘文件的 SHA256 保存 `keeper.db.pre-content-v1.<hash>.bak`，使用排他创建并核验字节，不覆盖已有备份。备份或写盘失败恢复迁移前内存，后续普通保存不会携带失败内容；设置页显示错误，重启重试。备份包含完整用户库，存放在原 userData 目录，应按用户数据库同等保护。

不修改生词、笔记、出处、复习、错题、作文、聊天、设置和旧作答。历史 attempt 增加提交内容版本；答案、题干、选项或客观题正文变化时，阅读器提示历史成绩已保留并允许重新作答，不用新答案重算历史分数。仅 rows/翻译/解析改变不使成绩过期。用户主动点击原有“重做”按钮仍按原契约清理作答和成绩。

## 分发库与构建

`stamp-content.mjs --db <input> --out <new-file>` 只生成新的候选文件，并校验所有原有业务字段逐条一致。构建和对齐候选流程也写入身份与内容版本，状态表记录整个目录修订。`build-db.mjs --out <new-file>` 可从原始材料重建到新候选，拒绝覆盖已有候选。仅分发构建执行 VACUUM 压实；不在用户库启动时增加压实工作。启动仍逐项核验实际字段，不依赖状态表跳过校验，以便恢复缺中间题和旧版遗漏。再次启动没有变更时不保存数据库。

## 后续边界

旧库首次迁移前如果题号/篇章位置已经改变且不能识别，将保留原记录并创建规范内容；后续发布必须保留已分配 source_id。目录中暂时缺少某套内置试卷时不自动删除该套试卷。整库备份暂不自动清理，恢复入口和备份保留策略放入第四批。剩余 7 篇 C 级对齐内容继续单独复核，本批不声明语义对齐已经全部正确。
