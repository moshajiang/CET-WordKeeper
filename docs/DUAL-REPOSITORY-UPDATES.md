# GitHub / 码云更新与源码同步

2026-10-19：新增码云仓库 https://gitee.com/moyunyi/cet-word-keeper.git 。公开 API 实测 HTTP 200、发行版列表为空；Git 远程当前没有分支。因此本次推送源码后，码云仍需上传发行附件才能提供应用更新。

## 实现

- 设置页可选择 GitHub / 码云，单独保存在本机界面偏好，不与 AI 配置或备份中的 Key 混用。发布页始终由主进程白名单决定。
- 码云使用自定义 electron-updater Provider（当前安装的 6.8.9 支持 custom）；分页读取公开 Releases，按语义版本选最新稳定版，排除草稿和预发布版本。最多扫描 2,000 个发行版，超过上限报错，不默默选择过期版本。
- 从真实发行附件地址读取 latest.yml。要求标签、清单版本一致；按精确附件名绑定当前版本的 NSIS 安装包；要求正整数大小和 SHA-512 校验。交由 electron-updater 下载、校验与安装，保留其校验机制；禁用码云多段范围请求。便携版仍只检测并前往发布页。
- 同一进程只有一条更新链。检查期间同来源复用请求，异来源拒绝；下载或待安装期间不能切源/重复检查。显式处理下载拒绝，避免未处理 Promise。事件带递增版本，界面不让迟到检查响应覆盖下载进度；卸载后不再订阅/改状态。
- 不做静默跨源降级。两个仓库可能不同步，用户可在失败后自行切换；缺失发行版、清单、安装包或校验值都会明确失败。

## 发布与推送

electron-builder 保留 GitHub publish 配置。Gitee 不是内置 provider，不能只把 publish 改成 gitee。两个平台上传**同一次构建**的 latest.yml、CET-WordKeeper-${version}-setup.exe；建议同时上传 portable.exe。码云标签使用 v${version} 正式语义版本；附件保持原名，不能重打包后沿用旧校验值。此任务只推代码，不创建发行版或发布安装包。

远程命名 origin（GitHub）和 gitee（码云）。npm run push:all 要求工作区已提交、远程地址准确，先对两边 dry-run，再依次推当前分支并校验远程提交 SHA。不使用 force / mirror，不删除分支，不推标签。跨服务推送无法全局原子化，部分失败时非零退出且报告状态，可修复凭据/网络后重跑；失败预检则不开始实际推送。

保留现有 release/v0.3.1 分支及历史，不合并到 main、不改版本号。同步包含此前用户授权优化形成的源码、回归、文档和项目分发种子，不含已安装程序、真实用户库、原始材料缓存或构建产物。

参考：[码云 API 文档](https://gitee.com/api/v5/swagger)、[electron-builder v26 更新文档](https://www.electron.build/v26/docs/features/auto-update/)。实现同时依据项目本地 electron-updater/out/providerFactory.js 和 providers/Provider.js 的当前契约。
