# 调度接口、间隔预览与 FSRS 本地对照

2026-10-25，P2 第二批。开发基线为 41ae548。本轮交付统一调度接口、评分间隔预览、可追溯的调度状态和只读对照工具；实际复习继续采用既有规则，尚未切换 FSRS。

## 使用方式

1. 生词或练习卡复习先独立回忆，翻面后查看三档评分对应的预计间隔，再选择评分。预览来自主进程同一调度接口；实际保存按当时状态重新计算。练习卡评分按钮同样直接使用接口返回的间隔。
2. 在设置页展开“复习调度评估（本地对照）”，选择 80%、90% 或 95% 的模拟目标保持率，点击“运行本地对照”。展开面板本身不运行计算。
3. 对照展示原安排与 FSRS 在最近一次评分后算出的下次时间。只检查当前学习中的生词及使用中、已加入队列的卡片，取最近有记录的最多 20 项，每项最多回放 200 次。
4. 缺少调度快照、起点无法确认、含“模糊”评分、时间异常、题面变化或状态断裂的项目明确跳过。旧历史不补写虚构快照；未作答内容单列为无历史。
5. 变更保持率后需要重新运行。结果不持久化，不修改实际到期时间、状态、作答记录、参数或每日额度；全部在本地计算，不调用模型。

目标保持率用于本次模拟，并非对实际记忆表现的承诺。本轮没有个人参数训练，没有以较长间隔或单次对照证明学习效果提高。

## 旧评分语义审计

原始评分为 0 不会/忘记、1 模糊、2 会用/记得。“模糊”可能包括回忆失败，也可能是成功但费力，旧记录无法区分。将这些数据直接映射为 FSRS Hard 会把部分失败当成成功。

因此本批只回放完整且评分均为 0/2 的项目：0 映射 Again，2 映射 Good；不虚构 Easy，不丢掉某一次模糊记录后继续拼接剩余历史。含 1 的整项历史跳过。此子集具有选择偏差，不代表所有词汇或卡片，也不用于训练个人权重。

## 数据与实现

- `electron/review-scheduler.cjs`：纯调度函数、状态规范化、间隔格式、三档预览和调度事件写入。词汇与卡片仍是两个明确的旧策略，公式和间隔边界保持原样。
- `review_schedule_event` 为增量表，主键 `(kind,log_id)`；保存项目身份、原日志身份、引擎/版本、原评分、时间、调度前后状态，以及卡片内容摘要。旧 `review_log`、`practice_attempt` 保留；基础 `SCHEMA` 必需字段不变。
- 新的审计事件与评分、日志、每日首次学习账本和操作防重记录使用同一事务。任一 SQL 或写盘失败全部回滚，重试不重复产生审计记录。迁移只建表，不给旧评分补造状态。
- `electron/fsrs-lab.cjs`：只在明确调用时加载 FSRS，验证连续历史和当前状态后逐条回放。没有写库能力，也没有应用模拟结果的 IPC。
- 审计核对日志/事件身份、评分、时间、策略版本、前后状态、调度结果和当前状态。题目/答案发生变化后，旧题历史不会自动用于新题模拟；单改标签或解释不影响内容身份。
- `SchedulePreview.vue`、`ScheduleLab.vue`：复习预览和设置页手动对照。标题等用户文本由 Vue 转义；离页后忽略迟到结果。

已有库可能暂时没有可对照项目，这是缺少可信连续历史的真实结果。本轮只为新的实际评分积累快照，不据此改变旧学习进度。旧记录仍可按原有方式正常复习。

## 后续切换与回退设计

本轮完成接口审计与可运行的离线对照，P2 尚未整体完成。下一批按以下顺序设计可选试用：

1. 明确新评分语义，区分“没想起”“想起但费力”“正常想起”“很轻松”；保存原评分及语义版本。历史三档继续保留，不修改成四档。
2. 先允许新卡小范围选择 FSRS。调度状态应按项目保存引擎、包版本、参数版本、记忆状态和学习阶段，不能仅用一个全局开关覆盖所有旧 due。
3. 切换前生成完整数据库备份，展示影响范围和下一轮负担；旧历史资格不足的项目保留原调度。切换以事务和操作身份提交，不通过反复回放悄悄调整所有到期时间。
4. 设计独立的回退策略，保留试用期所有作答和 FSRS 状态；回退不能以恢复旧备份的方式抹掉试用期间的真实学习。需要定义如何依据保留的评分更新旧策略，并验证中途重学、编辑、暂停和到期积压。
5. 在日志、日期、幂等和回退专项通过后交付用户可选试用。个人参数训练单独评估数据量与质量，不默认安装训练组件或上传学习记录。
