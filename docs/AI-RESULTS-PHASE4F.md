# 第四批 AI 结构化结果校验

日期：2026-10-19；源码版本 0.3.1。本批不发布、不替换安装程序、不对真实用户库做测试或修复。

## 问题与边界

原实现只验证服务响应中存在非空 content，便把它写进缓存。作文评分和试卷解析随后仅 JSON.parse，导致合法 JSON 中的错误类型、越界分数、缺字段、未知题号和非法答案可以进入业务表；坏结果也可能因缓存长期复用。解析题号通过删除题干所有非数字字符得到，题干包含年份时会串号；仅缺译文时，AI 还可能覆盖既有答案。

本批实现结构、身份和范围检查，不宣称能够自动判断译文、解析或评分的语义正确性。不批量改写旧真题或用户导入的既有答案。构建期离线生成脚本仍使用其已有校验流程，本批覆盖应用内 AI 请求。

## 校验规则

- `electron/ai-results.cjs` 为纯校验模块。接受完整 JSON 对象或完整 JSON 代码围栏；拒绝数组/null、拼接对象、截断内容和带多余说明的文本，不从任意字符串中猜测截取对象。结构化 content 最长 2 Mi 个字符；这是解码后的内容限制，不是网络传输体积限制。
- 评分为有限 number、范围 0–15、最多一位小数；不把字符串转数字，不静默钳位。band、issues、每条 quote/problem/fix 均有类型与长度要求；写作要求 strengths/improved，翻译要求 reference。只将已知字段写入评分业务结果。
- 新结构化响应在缓存前校验；旧缓存每次读取也校验。缓存内容或字段损坏时重新请求，成功后替换对应缓存；新响应仍不合格则不写业务和新缓存，不全表清理缓存，也不删除旧记录。
- 旧 essay.result 在读取时校验；异常返回 resultInvalid 与空结果给界面，提示保留草稿并重新批改。原始数据库字段不在读取时删除或重写。缺少新契约字段的旧评分同样标记，不自动捏造反馈内容；完整合法旧评分继续显示。
- 交卷补全只列出缺少答案的题目，不为缺少译文/解析额外请求 AI；答案齐全时无 Key 也可离线交卷。主动查看解析时，也补缺失的解析与译文，已有答案必须保持一致；译文已存在时不重写。优先使用题干明确的数字前缀作为题号，不拼接年份；无题号/重复题号通过稳定本地 ID 或不冲突的显式编号提示。只接受明确给出的整数编号，不按响应下标配题。
- 返回题数必须准确，题号不能遗漏、重复或未知。答案必须是实际允许集合内的单个大写字母；阅读限制 A–D，并在有选项时匹配界面实际首字母。匹配题沿用阅读器的段落按钮规则，允许同段重复；选词填空限制实际词库/A–O、同词不重复，并排除已知答案。缺少可识别选项时只能检查题型范围，不能据此保证材料本身完整。
- 每篇结果全部校验通过才保存；一条答案不合法则该篇译文和全部答案均不写入。已有答案/解析/译文以及其他请求先完成的字段不被迟到响应覆盖。多篇任务之前已成功的篇章保留，当前有效作答草稿在事务中随答案版本重新绑定；交卷失败不创建成绩。
- 写盘仍遵循既有事务/快照回滚。有效缓存已单独提交但后续业务写盘失败时，该有效缓存可供重试；这不等同于缓存异常响应。取消检查继续在 await 后和持久化前生效。
