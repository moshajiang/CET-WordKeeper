# 自动检测更新与版本提醒

2026-10-30。已实现源码功能，需随下一次正式安装包发布后使用；已发布 v0.3.3 的安装文件和标签没有改变。

## 使用方式

“设置 → 版本更新”默认开启“自动检查并提醒新版本”。安装版和便携版启动约 15 秒后检查，正常运行期间约每 6 小时一次；如果上次检查仍在有效间隔内，重启不会反复请求。支持原有 GitHub / 码云更新源，沿用已有选择；首选失败时自动尝试另一来源，保留用户的首选。

发现新版本后，右下角显示非弹窗提醒，切换页面仍保留，不抢走阅读或输入焦点。自动检查只获取版本信息，不下载附件、不安装、不重启。可选择：

- **下载更新**：安装版由用户主动开始下载，显示进度；完成后再次点击“安装并重启”才调用安装器。请先保存当前内容。正常退出不会自动安装。
- **前往下载**：便携版打开实际检查来源的固定发布页，不调用应用内安装器。
- **稍后提醒**：当前版本静默 24 小时，之后可重新提示；另一个新版本不受旧版本延迟影响。
- **跳过此版本**：不再自动提醒该版本；更高的新版本仍提示。手动检查仍可重新发现、下载被跳过的版本。

设置页显示首选来源、上次/下次自动检查时间及已跳过版本。关闭自动检查会清理后续计时，禁止在途请求结果弹出新的自动提醒；已有手动下载不会因此取消。手动“检查并下载更新”沿用旧安装版的检查后下载行为，便携版则只检查。全局提醒的下载入口直接使用已确认版本，无需再次检查。

程序运行期间才会检查；退出后不会注册常驻服务、系统开机启动或额外后台进程。未启用系统通知，提醒显示在软件内。开发环境不自动联网，仍可手动检查，设置页有相应说明。

## 异常与数据边界

两个源都失败时不会误报为“已是最新版本”；错误保留在设置页，不反复弹窗。失败退避约为 30 分钟、1 小时、2 小时、4 小时，最长 6 小时。网络检查、下载和待安装期间不同时切换 Provider；已有下载完成后，自动任务不重复检查或下载。

偏好与时间保存在用户数据目录的 `update-preferences.json`，仅包含更新设置与提醒元数据，不包含学习记录、API 配置或凭据。不修改数据库表、学习进度、分发种子或备份内容。文件以独占临时写入、刷盘/摘要校验、原子改名保存，失败保留旧文件。损坏文件暂停自动检查，等待用户在设置中明确保存，不由启动迁移静默覆盖。

首次使用会把现有 `keeper.update.source` 浏览器偏好迁移到主进程设置，之后以持久化设置为准。延后和跳过状态跨重启保留；提醒按版本区分。运行中及重启后的系统时间回退会重新安排检查，恢复/退出时停止自动任务。

仍使用已有 electron-updater 下载与安装校验。码云沿用正式发行版、唯一 latest.yml、同版本安装附件、大小和 SHA-512 校验；任意更新 URL 或发布页来源不被接受。只有正确发布新版本及附件才会被检测，单纯推送源码不会成为可安装更新。旧 v0.3.3 应用不会仅因本批源码提交就获得新启动检测功能。

## 实现与验证

新增 `electron/automatic-updates.cjs` 负责启动延迟、节流、来源回退、失败退避、提醒偏好与计时器。`electron/updates.cjs` 增加检查模式、显式下载和在途状态；关闭退出自动安装。主进程在完成用户数据初始化与页面加载后启动，在系统恢复时唤醒检查，恢复数据库和退出时停止。

新增 `UpdateNotice.vue`、`AutomaticUpdateSettings.vue`，分别接入 App 全局提醒和原设置页。新 IPC 为 update:download/preferences/dismiss，返回统一递增版本快照，迟到响应不覆盖新进度。下载启动后即时返回状态，提醒可在下载中延后；安装、发布页均由显式点击触发。

运行 `npm run test:updates`：原 25 项双来源/推送/设置数据检查、新增 20 项自动状态检查、原 7 项设置真实界面、新增 19 项自动提醒真实界面，合计 **71 项相关检查**通过，生产构建通过。覆盖假时钟、重启节流、运行中时钟回退、关闭/重新开启、稍后与跳过、失败回退、下载重试、设置损坏/写盘失败、跨页提示、便携版、恢复偏好、手动安装和 IPC 白名单。

真实界面测试只在隔离进程中替换更新器/安装器和时钟，未使用产品测试开关，没有下载或安装真实附件、打开外部网页、操作真实用户数据。未运行无关全量 CI，未验证新的打包安装成品或发布线上新版本。当前仍是源码交付，安装包需另行构建验证发布。
