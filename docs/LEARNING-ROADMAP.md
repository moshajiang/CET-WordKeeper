# CET WordKeeper 分阶段开发方案

2026-10-25。基线为 6412f8f。方案围绕「真题理解 → 可检验的练习 → 持续复习 → 跨场景使用」，按阶段交付可用功能。各阶段完成相关验证后再推进下一阶段，不以新增按钮数量代替学习效果。

## 阶段与验收

| 阶段 | 交付内容 | 完成标准 | 当前状态 |
| --- | --- | --- | --- |
| P1 独立练习卡片 | 从资料手动建卡、把现有自测存为卡片、AI 批量生成候选卡；审阅编辑、选择保存；独立复习与作答历史；来源快照 | 不调用 AI 也能建卡和复习；生成结果不自动入库；刷新/重启不丢卡片；每卡独立调度；评分重试不重复；旧库与旧知识点队列兼容 | 已完成，源码阶段通过验证 |
| P2 复习调度与负担 | 新词/新卡数量和本轮时长设置、暂停/重学、到期积压处理；评估并引入 FSRS | 保留旧复习日志，迁移可回退；新旧调度对照测算；不把忘记记为成功；日期与时区边界正确；在真实试用中观察负担 | 学习量、短轮次、调度接口与只读对照已完成；可选试用/回退待开发 |
| P3 短语与熟词生义 | 划选短语收藏、一个词多个语境义、遇见记录、拼写与原句填空 | 不把词形当成独立词重复计数；短语和单词可独立复习；每个语境义有真实出处；导出保留来源 | 待 P2 完成 |
| P4 移动复习与同步 | 先做轻量移动复习入口，再加入离线队列、设备配对与冲突合并 | 断网后评分保留；重复同步不重复评分；身份认证与解绑有效；冲突不静默覆盖；明确备份恢复和隐私边界 | 待独立设计 |

P1 沿用已有简易间隔规则，不宣称个性化最优调度。P2 需要先核对当时 FSRS 库、许可证和参数格式，再决定接入方案，不自行仿造其公式。P4 在本地桌面功能稳定后单独评审认证与同步方案，不在现有安装包内仓促开放网络服务。

## P1 用户流程

1. 在知识库打开一条资料，点击“制作练习卡”。可以选择“把自测存成卡片”“手动新建”或“AI 生成候选卡”。
2. 候选卡展示题型、题目、选项、答案、解析和标签；用户可编辑、取消勾选，再点击保存。AI 请求期间可停止，切换来源后迟到结果不覆盖新页面。
3. 保存后进入卡片管理，可按来源、标签、题型和状态筛选。支持编辑、加入复习、暂停、继续、归档及恢复。恢复归档卡默认暂停，避免突然增加到期负担。
4. 复习页新增“练习卡”入口，先作答再展开答案；客观题给出对照，主观题由用户核对后自评。每张卡独立计算下一次时间。
5. 详情显示卡片的作答记录、当时题目答案及来源快照。来源资料删除或变化时提示；卡片和已有历史仍可阅读，不自动改写题目或清除历史。

## P1 数据约定

- 独立建表，不把练习卡混进 kb_entry 正文，不修改词汇调度算法，也不隐式转换旧 knowledge_review 记录。
- 卡片使用 UUID，包含题型、题面、答案、选项、解析、标签、来源 key、来源快照/摘要、版本、状态、到期时间与复习计数。
- 题型先支持问答、翻译、判断、选择。客观答案和选项在主进程严格校验；模型输出只是候选数据。
- 作答记录保存当时的卡片版本快照、用户答案、自评分、客观对照结果及下次时间；记录不随卡片编辑重写。
- 创建批次与评分分别携带操作身份。相同请求重试返回原结果；不同内容复用身份、过期编辑或过期复习请求明确拒绝。
- 批量保存前整批验证，在事务中统一写盘；任何一项无效或写盘失败均不留下部分数据。
- 重复题面按来源、题型及选项识别，不无提示创建重复卡。编辑会检查版本；改变题目/答案等测试内容时重新学习，保留历史。
- 使用增量建表迁移，原始备份必需字段集合保持不变，兼容旧数据库。所有测试使用隔离数据库，不访问真实学习记录或付费模型。

## P1 开发顺序

1. 数据服务、增量迁移、批次/评分幂等、来源快照与历史。
2. IPC 与候选题生成校验，补充边界和回滚数据测试。
3. 卡片管理及知识库入口，加入审阅、编辑与筛选。
4. 练习卡复习页与历史详情，串联首页到期提醒。
5. 真实 Electron 页面专项验证、构建、密钥检查，更新交接文档并同步两个源码仓库。

## 验证与发布

重点检查非法模型结果、重复点击、过期版本、取消与迟到请求、写盘失败、重启保留、来源变更/删除、归档恢复、旧队列兼容、客观题答案对照以及主观题不伪造自动评分。

完成源码阶段后单独更新安装包版本并验证打包成品，再发布 GitHub 与码云。已发布 v0.3.3 的标签与附件保持不可变；新功能不能继续覆盖旧版本附件。

## P2 下一步执行顺序

1. **先控制学习负担**：分别设置每日新词/新卡数量、本批上限和目标时长；明确今天已完成、新增和逾期统计口径。将设置放进已有本地设置与备份，校验上下限，避免负数或超大队列。
2. **处理积压与暂停**：在首页和复习开始前显示预计量；提供只复习到期内容、少量新内容、暂缓新卡等选择；恢复暂停不突然塞入大量新卡。不静默推迟到期时间，不伪造完成记录。
3. **再评估 FSRS**：核对官方实现、许可证、运行环境、日志要求和参数版本；先做独立调度接口与离线对照，不立即替换线上算法。词汇旧日志与新卡日志分开审计，明确三档自评如何映射及其局限。
4. **验证后切换**：旧记录迁移前保留完整备份和算法版本；检查重复评分、跨天/时区、重学与撤销、逾期卡和离线日期变化。用户能理解下一次安排，回退不丢作答历史。

P2 分小批提交：先交付每日学习量及统计，再处理积压，最后决定调度算法。每批只跑影响范围内的检查；新安装包待明确版本后另行打包验证发布。

## P3/P4 设计约束

- 短语收藏需要记录真实划选和原文身份；熟词生义先允许用户手动选义/补充，再提供 AI 建议。一个语境义对应自己的练习目标，不能把所有词义混成一张超长卡。
- 移动端先验证小范围可用的复习体验，再决定 PWA/原生壳和服务方案。同步至少具备设备身份、增量游标、幂等操作、冲突副本及解绑；桌面本地学习与导出始终能独立工作。
- 认证服务、托管成本和账号数据边界需要单独的可审阅设计，不在 P1 中预先引入网络依赖。
