## 一、诊断结论（当前 v0.2.10 的残余问题）

用「数字锚点偏移分析」量化（锚点 = 原文中的年份/百分比/金额等数字，译文中基本原样保留）：

| 指标 | 数值 | 说明 |
|---|---|---|
| 锚点行内命中 | 579（约 69%） | 这些行对应正确 |
| **邻行漂移** | **83 处** | 锚点落在 ±1~±5 行：**对应错误** |
| 无锚可判 | 275 处 | 译文把数字汉化/未保留，无法用锚点判定 |
| 漂移篇章 | 19 篇 ≥2 处偏移 | 最严重：CET6 2014.6 set1 match（7/56 行偏移） |

偏移直方图：`+1×37、-1×19、+2×9、-2×10、±3~5×5` —— **双向带内漂移**为主。

**根因**：现引擎在「句数差 ≤2」时走 1:1 按序配对（占全库 74%）。标题行、并句、漏译这些局部差异会让错位**顺延到段落结尾**（错一行就错到底）。简版 DP 只在句数差 >2 时启用，且代价函数只有长度比、无概率模型、无锚点集合运算——纠错能力不足。

## 二、理论与现成实现调研

| 方案 | 特点 | 评估 |
|---|---|---|
| **Gale-Church (1993)** | 句长统计 DP：z = (zhLen − enLen·c)/√(enLen·s²)，正态分布概率代价，罚分表区分 1-1/1-2/2-1/2-2/1-0/0-1 | 经典，长度-only 在噪声语料会「错误蔓延」 |
| **Champollion (LDC, Ma 2006)** | 中英对齐专用：DP 求最大相似路径（允许 1-1 到 4-1），**用翻译词典做词汇相似度评分**——恰好我们有 ECDICT 2.8 万词 | 与我们场景完全吻合，词典评分是质变点 |
| **multi-align (GitHub, MIT)** | 纯前端零依赖 JS：Gale-Church 正统实现（erf 概率 + Table 5 罚分表 + 数字锚点 Dice + 段落锚定 + 滑窗分块），自带金标准基准与已知陷阱文档（滑窗右填充问题等） | **可直接移植**：MIT 许可、单文件 js/aligner.js、纯浏览器环境与我们一致 |
| hunalign wasm / Vecalign | hunalign 需 wasm 打包；Vecalign 需句向量模型（MB 级） | hunalign 备选；Vecalign 客户端不可行 |

结论：**移植 multi-align 的 DP 骨架 + 嫁接 Champollion 的词典评分路线（用内置 ECDICT）**，不引入任何外部依赖。

## 三、改动清单（文件级）

### 阶段一：DP 对齐核心（质量决定性改动）

| 文件 | 改动 |
|---|---|
| `src/utils/bilingual.js` | ① 移植 alignPair DP（erf/pd 概率函数、PEN={11:0,12:230,21:230,22:440,10:450,01:450}、Float64Array 格点、回溯产 beads）；② 新增 `prepareSent()`：每句预计算 len(EN 词数/ZH 字数)、nums(数字锚点集)、lex(词典译名集)；③ 新增 beadCost：z 值概率代价 + 数字锚点 Dice 奖励 + **ECDICT 词典 Dice 奖励**；④ `alignDP()` 替换现有 pairSentences 的非 1:1 分支与简版 DP；⑤ 段落锚定（usePara）与 markerAligned（字母软退化）保留 |
| `scripts/build-db.mjs` | 构建期生成「英→中译名候选表」：扫 ECDICT 的 exchange/translation 字段，产出 `en→[zh 候选词]` 映射打进 keeper.db 新表 `dict_lex`（供运行时 O(1) 查询） |
| 文件头 | 保留 multi-align 版权声明（MIT），注明移植与修改 |

**中英校准**（关键，否则 z 值无意义）：EN 长度用**词数**、ZH 长度用**汉字数**，c（基准比）与 s² 从全库统计——构建期对 311 篇已正确对齐的篇章估计，写为常量（预期 c≈0.55~0.6，参考香港 Hansard 汉英 c≈1.6 是「中文字数/中文字数」口径不同，以实测为准）。

**词典评分细节**：EN 句实词（去停用词、经 word-forms.json 词形还原）→ 查 `dict_lex` 得中文候选集（一词多译取全部）→ 候选串的 2-gram 与 ZH 句 2-gram 求 Dice。预计算每句的候选集，DP 格点内只查表，无性能问题。

## 四、已知边界（诚实声明）

1. **孤立漏译（1-0/0-1）仍是 DP 类算法的原理性弱项**（multi-align 基准文档也承认）——词典评分可显著缓解但不能根治；这类行占比很小，且兜底合并保证不丢内容
2. 数字汉化的译文（「30%」→「百分之三十」）锚点失效——词典评分部分补偿；可在锚点提取时加中文数字转换（一期不做）
3. 无句向模型（LaBSE）的语义级校验——客户端体积不允许，不在本方案范围
