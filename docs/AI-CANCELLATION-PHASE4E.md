# 第四批 AI 取消与聊天清空隔离

日期：2026-10-19。源码版本仍为 0.3.1；不发布，不修改真实用户数据或已安装程序。

## 原问题与实现

旧版聊天清空只删除已有行，等待中的回复随后仍会写入 user/assistant 两行，历史因此复活。划选翻译/语法未绑定请求身份，旧请求可以覆盖新请求或下一篇章的卡片。页面离开或配置改变只忽略部分返回值，没有结束网络请求；聊天发送 IPC 失败还可能使按钮持续忙碌。

- 主进程 `ai-requests.cjs` 管理每个窗口的请求 ID、类型、AbortController 与结束清理，拒绝重复在途 ID 和无效 ID；取消不能操作其他窗口的请求。旧调用方可不传 ID，主进程仍生成身份并参加聊天清空及窗口销毁取消。
- 网络请求组合用户取消与既有超时信号，覆盖 fetch 和响应正文读取；每个 await 后、缓存/业务结果写入前再次检查请求状态，防止不遵守 abort 的传输返回迟到数据。主动取消返回 cancelled，超时返回 timeout。
- 前端 `ai-tasks.js` 在取消 IPC 前先使本地身份失效；即使取消 IPC 失败，旧回调也不能覆盖当前结果。解析/交卷取消保留请求身份等候取消回执，以完成部分结果后的草稿版本重新绑定。
- 支持整句请求、聊天生成、作文批改、整卷解析/交卷和连接探测的取消按钮。切篇取消与篇章绑定的划选、批改和聊天；离开阅读器取消全部任务，窗口销毁/整页加载也由主进程兜底。修改连接配置或离开设置页取消探测，修改作文取消旧批改。
- 清空历史采用事务持久化；成功后递增聊天代次并取消旧聊天。发送捕获代次，保存前重新检查；两个角色的消息一起提交。清空/发送写盘失败恢复原内存，不留下半条对话。
- 作文评分和每个篇章的解析更新采用事务持久化。取消后不再请求后续篇章，已经提交的篇章结果保留；每篇解析的事务同步将当前有效 answer_draft 绑定新内容版本，直接离开页面也不会使原选项变成过期草稿。取消交卷不创建新的成绩或正式作答。
- 历史读取也校验界面序号；清空、发送、切页使旧历史加载失效。发送失败释放忙碌状态并保留问题供重试；停止生成移除未保存的占位消息，清空失败显示错误并重新读取已保存历史。

取消以本地处理状态为边界：已完成事务的内容保留，不回滚已经完成的请求；取消 HTTP 连接不承诺外部提供商立即停止计算。已有离线内容和有效缓存继续使用。
